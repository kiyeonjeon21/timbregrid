# Real Server Demo

This walkthrough shows TimbreGrid's strongest current value: checking a real OpenAI-compatible TTS server before wiring it into a client such as Open WebUI.

The flow produces two local artifacts:

- `demo-assets/speaches-direct.wav`: audio generated directly by the server.
- `demo-assets/speaches-doctor.json`: TimbreGrid's compatibility report for the same server, model, voice, and response format.

`demo-assets/` is ignored by git. Do not commit local audio or doctor reports.

## 1. Start Speaches

This demo uses Speaches because it exposes an OpenAI-compatible speech endpoint and can run Kokoro through a Docker image.

```bash
docker run \
  --rm \
  --detach \
  --publish 8000:8000 \
  --name speaches \
  --volume hf-hub-cache:/home/ubuntu/.cache/huggingface/hub \
  ghcr.io/speaches-ai/speaches:latest-cpu
```

Download and confirm the Kokoro TTS model:

```bash
export SPEACHES_BASE_URL="http://localhost:8000"
uvx speaches-cli registry ls --task text-to-speech
uvx speaches-cli model download speaches-ai/Kokoro-82M-v1.0-ONNX
uvx speaches-cli model ls --task text-to-speech
```

## 2. Generate Audible Evidence

```bash
mkdir -p demo-assets

curl "$SPEACHES_BASE_URL/v1/audio/speech" \
  -H "Content-Type: application/json" \
  --output demo-assets/speaches-direct.wav \
  --data '{
    "model": "speaches-ai/Kokoro-82M-v1.0-ONNX",
    "voice": "af_heart",
    "input": "TimbreGrid is checking a real OpenAI compatible text to speech server before it is connected to an app.",
    "response_format": "wav"
  }'
```

Play `demo-assets/speaches-direct.wav` locally. This proves the server can synthesize audio independently of TimbreGrid.

## 3. Run TimbreGrid Doctor

```bash
uvx --from timbregrid==0.1.0a2 timbregrid doctor "$SPEACHES_BASE_URL/v1" \
  --model speaches-ai/Kokoro-82M-v1.0-ONNX \
  --voice af_heart \
  --response-format wav \
  --output demo-assets/speaches-doctor.json
```

Expected successful shape:

```text
OK doctor: 11/11 conformance cases passed
open_webui_tts: ready - basic OpenAI-compatible /v1/audio/speech request returned audio
pipecat_openai_tts: likely_ready - OpenAI-style speech request, speed, and instructions fields passed basic checks
```

If the report fails, inspect the failing cases before changing client settings:

```bash
jq '.summary, .integration_readiness, .conformance.cases[] | {name, passed, status_code, content_type, failure}' \
  demo-assets/speaches-doctor.json
```

## 4. Inspect The Evidence

Open the local viewer from the repository root:

```bash
python -m http.server 8765
```

Then visit:

```text
http://localhost:8765/examples/doctor-report-viewer.html
```

Load `demo-assets/speaches-doctor.json`, then attach `demo-assets/speaches-direct.wav` in the Evidence Audio panel.

Use the TTS Backend Preflight panel to confirm:

- the doctor report passed;
- `open_webui_tts` is `ready`;
- an audio file generated by the same server is attached;
- the base URL, model, voice, and response format match what you plan to configure in a client.

## 5. Wire A Client

For Open WebUI, use the TimbreGrid report as a preflight check before editing settings. See [`integrations/open-webui.md`](integrations/open-webui.md) for the backend configuration guide.

TimbreGrid does not certify a full client integration. It checks the selected server's basic OpenAI-compatible TTS behavior and makes the evidence easy to inspect.

## Cleanup

```bash
docker stop speaches
rm -f demo-assets/speaches-direct.wav demo-assets/speaches-doctor.json
```
